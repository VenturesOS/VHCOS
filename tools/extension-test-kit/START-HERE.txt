VHC IDENTITY TEST EXTENSION

1. PREPARE EMERGENT
Run GitHub branch codex/identity-resolution in your Emergent preview.
Follow docs/IDENTITY_RESOLUTION_TESTING.md for the backend and database indexes.
Enable your login email in EXTENSION_CHECK_EXISTING_ALLOWLIST.
Verify the preview uses a test database (check mongo_production_override.py too).
This ZIP contains the browser extension only. It does not start a backend.

2. INSTALL IN CHROME
Extract the ZIP to a permanent folder.
Use a separate Chrome profile, or disable your normal VHC extension while testing.
Open chrome://extensions, turn on Developer mode, and click Load unpacked.
Choose the extracted folder containing manifest.json. Pin VHC Identity TEST.
Refresh any candidate tabs that were already open.
Official instructions: https://developer.chrome.com/docs/extensions/get-started/tutorial/hello-world#load-unpacked

3. CONNECT
Open VHC Identity TEST. Enter your Emergent preview base URL without /api.
Use your preview login. No production URL is prefilled.
Known production portal addresses and their relay are blocked.
Emergent preview domains and localhost are supported. For a custom preview
domain, rebuild with --backend-url using backend/scripts/build_test_extension.py.
Preview health alone cannot prove that its database is separate from production.

4. CHECK PERFORMANCE
Open the popup link "Open test performance report".
Check the preview connection, then browse candidate search pages normally.
Start with 10-20 visible profiles; repeat on a larger normal search page.
Refresh the report to see median/P95 matching timings, decision counts,
submission/poll timings and errors. Matching timings include all request batches
but exclude DOM scraping/rendering. Capture timings exclude AI extraction.
No load is generated by the report itself.
The report retains the latest 300 calls locally and can download a JSON report.

5. CHECK ACCURACY AND RETRIES
Use examples whose identities you independently know. Include identical names
and employers, different cities, changed jobs, masked contacts and sparse cards.
Record correct, wrong, missed and uncertain results in the report before export.
The counts describe your sample; they are not a 99% accuracy certification.
Auto-capture defaults to off. Use Capture or an explicit context-menu capture.
Expect "Awaiting review"; resolve it through Admin > Identity Review.
Check that retrying the same operation does not create a second observation.
Test an outage: expect unavailable, not a confirmed absent/duplicate candidate.

6. SHARE RESULTS
Click Download report to save VHC-extension-test-report.json.
It contains timings, outcome counts and your manual totals; no candidate names,
IDs, contact details, auth tokens or page URLs are included by the report.
Normal extension storage still contains its own login/capture information.
Send the report back for analysis before a production extension release.

The test package uses the branch's actual matching/capture code with timing
wrappers, preview URL protection, no update feed and manual-capture defaults.
Production manifests and source files are not modified by the builder.
Do not publish this test ZIP as your production extension.
