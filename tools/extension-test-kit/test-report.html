Check these cases before deployment

  1. Same name and employer, different cities: inspect the evidence and alternatives.
  2. Identical visible details: expect ambiguity rather than identity confirmation.
  3. Changed job or city: check reviewed historical context in Identity Review.
  4. Hidden contact details: no invented email or phone evidence.
  5. Capture and retry: expect “Awaiting review” and no duplicate observation for the same operation.
  6. Disconnected backend: expect unavailable/incomplete, never proof of absence.

Setup

Use a separate Chrome profile or disable the production extension while testing. Log into this test extension with your Emergent preview base URL (without /api). The preview must run branch codex/identity-resolution with your email enabled in EXTENSION_CHECK_EXISTING_ALLOWLIST. Confirm it uses a test database.

Auto-capture defaults to off; use the capture button for deliberate tests. Matching still runs on supported search cards. Known production portal addresses are blocked in this package. A preview address alone does not guarantee its backend uses a test database.

Downloaded reports contain timings, outcome counts and build details. They exclude candidate names, IDs, page URLs, contact details and authentication tokens. The underlying extension retains its normal capture/login storage separately.
